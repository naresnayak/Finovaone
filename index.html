Technical Architecture Breakdown

Async Message Queue & Lock-Free Architecture

How we resolve concurrent external API requests attempting to update inventory or financial ledgers simultaneously.

1. External Ingestion

E-Com / DMS / Bank APIs push high-volume JSON payloads

2. Worker Queue

Payload queued; immediate HTTP 202 response returned (0 sec lock)

3. Concurrency Throttle

Sequenced execution worker with exponential backoff on table lock

4. Database Commit

Atomic commits (`Company.StartTransaction`) into In-Memory DB

Why standard ERP APIs fail under load: When 50 concurrent webhooks hit the API or Service Layer simultaneously to update the same stock item or account ledger, database engines trigger table locks resulting in severe transaction deadlocks. By introducing an in-memory worker queue, transaction bursts are flattened into non-blocking sequential batches without dropping requests.
